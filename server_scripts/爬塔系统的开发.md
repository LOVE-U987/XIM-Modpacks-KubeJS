# 爬塔系统 (Tower System) 实现文档

## 系统概述

这个爬塔系统是基于KubeJS 7.x开发的Minecraft模组功能，允许玩家参与渐进式难度的爬塔挑战。系统提供了可配置的难度递增机制、多种奖励类型和丰富的命令接口，让玩家能够在一个动态变化的环境中挑战自己的极限。

## 文件结构

```
kubejs/
└── server_scripts/
    ├── tower_scaling.js       # 爬塔系统的主要实现文件
    ├── difficulty_scaling.js  # 动态难度系统（与爬塔系统兼容）
    ├── README_TOWER_SCALING.md  # 本说明文档
    └── README_DIFFICULTY_SYSTEM.md  # 动态难度系统文档
```

## 核心功能

1. **渐进式难度系统**：每层怪物的生命值、护甲和伤害都会随着楼层增加而增强
2. **多波次怪物生成**：每层包含多个波次的怪物，最后一波为BOSS波
3. **丰富的奖励机制**：包括经验值、特殊物品和掉落物增益等
4. **完整的命令系统**：提供多个命令接口，方便玩家控制爬塔过程
5. **时间限制挑战**：每层有时间限制，增加游戏紧张感
6. **玩家进度跟踪**：记录玩家的最高楼层和当前进度

## 奖励机制详解

系统实现了多种奖励类型，以激励玩家不断挑战更高楼层：

- **每5层基础奖励**：提供经验值奖励，经验值数量随楼层指数增长
- **每10层特殊奖励**：随机给予稀有物品，从预设的战利品表中生成
- **每20层增益奖励**：激活"怪物掉落物增益"效果，持续5层，增加怪物掉落额外物品的几率

## 命令系统

爬塔系统提供了完整的命令接口，玩家可以通过以下命令控制爬塔过程：

| 命令 | 功能描述 | 权限要求 |
|------|---------|---------|
| `/tower` | 打开爬塔系统主菜单 | 所有玩家 |
| `/tower start` | 开始新的爬塔挑战 | 所有玩家 |
| `/tower next_floor` | 前往下一层（完成当前层所有波次后） | 所有玩家 |
| `/tower next_wave` | 前往下一波（完成当前波次的怪物击杀后） | 所有玩家 |
| `/tower end` | 结束当前爬塔挑战 | 所有玩家 |
| `/tower status` | 查看当前爬塔状态 | 所有玩家 |
| `/tower settings` | 查看爬塔系统设置 | 所有玩家 |
| `/tower debug console on/off` | 开启/关闭控制台调试模式 | 管理员 |
| `/tower debug chat on/off` | 开启/关闭聊天栏调试模式 | 管理员 |

## 配置选项

爬塔系统的核心配置位于 `tower_scaling.js` 文件顶部的 `TOWER_CONFIG` 对象中：

```javascript
const TOWER_CONFIG = {
    // 基础配置
    BASE_TOWER_HEIGHT: 1,        // 起始楼层
    MAX_TOWER_HEIGHT: 100,       // 最高楼层
    FLOOR_DIFFICULTY_MULTIPLIER: 0.1, // 楼层难度乘数
    TOWER_REGION_SIZE: 64,       // 塔区域大小
    DETECTION_RADIUS: 32,        // 检测半径
    
    // 难度配置
    MIN_HEALTH_MULTIPLIER: 1.0,  // 最小生命值倍率
    MAX_HEALTH_MULTIPLIER: 5.0,  // 最大生命值倍率
    MIN_ARMOR_MULTIPLIER: 1.0,   // 最小护甲倍率
    MAX_ARMOR_MULTIPLIER: 3.0,   // 最大护甲倍率
    MIN_DAMAGE_MULTIPLIER: 1.0,  // 最小伤害倍率
    MAX_DAMAGE_MULTIPLIER: 2.5,  // 最大伤害倍率
    
    // 奖励配置
    REWARD_INTERVAL: 5,          // 基础奖励间隔（楼层）
    BASE_XP_REWARD: 100,         // 基础经验奖励
    XP_MULTIPLIER_PER_FLOOR: 0.2, // 每层经验倍率
    
    // 怪物入侵波次配置
    WAVE_COUNT: 6,               // 每层波次数
    WAVE_SPAWN_INTERVAL: 10,     // 波次生成间隔（秒）
    TIME_LIMIT_PER_FLOOR: 300,   // 每层时间限制（秒）
    
    // 调试配置
    DEBUG: false                 // 全局调试标志
};
```

### 配置修改指南

要修改爬塔系统的配置，您需要编辑 `tower_scaling.js` 文件中的 `TOWER_CONFIG` 对象。修改后，需要重启Minecraft服务器以使更改生效。

**重要提示**：过度调整某些参数可能会导致游戏平衡性问题，建议在修改前备份原始文件。

## 爬塔流程详解

1. **开始挑战**：玩家使用 `/tower start` 命令开始爬塔挑战
2. **怪物波次**：每层包含多个波次的怪物，从普通怪物到精英怪物再到BOSS
3. **进度追踪**：系统会跟踪玩家击杀的怪物数量，当达到要求时可以进入下一波
4. **时间限制**：每层有时间限制，超时将重置当前楼层进度
5. **完成楼层**：完成所有波次后，使用 `/tower next_floor` 前往下一层
6. **获取奖励**：在特定楼层获取经验值、物品和增益效果
7. **结束挑战**：使用 `/tower end` 命令结束当前挑战，系统会记录最高楼层

## 与动态难度系统的兼容性

爬塔系统与动态难度系统（`difficulty_scaling.js`）完全兼容。爬塔系统会标记塔内生成的怪物，并确保两种系统不会重复增强同一怪物，避免出现过度困难的情况。

## 怪物强化机制

每层的怪物都会根据当前楼层进行强化，强化程度由以下公式计算：

```
强化倍率 = 基础倍率 + (最大倍率 - 基础倍率) * 进度 * (1 + 楼层难度乘数)
进度 = (当前楼层 - 1) / (最高楼层 - 1)
```

强化效果包括：
- 生命值提升
- 护甲值增加
- 伤害输出提高

## 调试功能

爬塔系统提供了内置的调试功能，管理员可以通过命令开启/关闭调试模式，以便排查问题：

- **控制台调试**：在服务器控制台显示详细的系统运行信息
- **聊天栏调试**：向玩家发送额外的调试信息

## 性能优化

为了确保爬塔系统不会对服务器性能造成过大影响，系统采用了以下优化措施：

- 使用高效的数据结构（如Map）存储玩家进度
- 限制事件处理频率，避免过于频繁的计算
- 精确的实体过滤，只处理需要强化的敌对生物
- 适当使用异步操作，避免阻塞主线程

## 故障排除

如果在使用爬塔系统时遇到问题，可以尝试以下解决方法：

1. **确认脚本已加载**：检查服务器日志，确认 `tower_scaling.js` 已成功加载
2. **检查权限**：确保玩家拥有足够的权限使用爬塔命令
3. **查看调试信息**：开启调试模式，获取更详细的系统运行信息
4. **检查配置文件**：确认 `TOWER_CONFIG` 中的配置参数设置合理
5. **验证兼容性**：确保与其他模组没有冲突，特别是与实体生成和修改相关的模组
